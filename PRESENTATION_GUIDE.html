1. 30-Second Elevator Pitch (Memorize This!)

"Good morning respected judges. Current hotel check-ins and transit checkpoints rely on physical ID photocopies or central databases—causing frequent privacy leaks, identity theft, and fake ID fraud.

VeriChain is a Self-Sovereign Decentralized Identity (DID) Platform built for Indian GovTech and Tourism. It implements Zero Raw PII on-chain in full compliance with the DPDP Act, 2023.

When an authority issues a credential, only its deterministic SHA-256 cryptographic hash is anchored to the blockchain. The citizen holds the raw ID in their private wallet. When checking in at a hotel, the verifier scans a dynamic QR code, calculates the hash in real-time, and validates it against the blockchain in under 100ms with zero data leakage."

2. Executive Problem & Solution

The Real-World Problem VeriChain's Architectural Solution
Identity Theft & Photocopy Leaks: Physical Aadhaar/Passport copies left at hotel front desks get stolen or misused. Zero Raw PII On-Chain: Raw data stays exclusively on the citizen's device. Only mathematical hash commitments exist on the ledger.
Forged & Altered IDs: Fake IDs and altered PDFs are easy to produce with basic photo editing. Deterministic Hash Matching: Modifying even 1 digit in an Aadhaar number changes the SHA-256 hash completely (avalanche effect), triggering an instant Tamper Detected alert.
Central Database Vulnerabilities: Central servers are single points of failure prone to insider tampering. Immutable Blockchain Ledger: Blocks are cryptographically chained with previous hashes on Polygon Amoy EVM testnet, preventing silent alterations.
Slow Revocation: Revoking a compromised tourist pass or national ID takes days across disparate databases. Instant On-Chain Revocation: Authorities or citizens can broadcast instant CREDENTIAL_REVOKED blocks to blacklist compromised credentials in real-time.

3. Complete File & Function Guide

Backend Engine (server/)

  • server/ledger.js:
    • computeCredentialHash(payload): Sorts all JSON keys alphabetically (Object.keys().sort()) and generates a deterministic SHA-256 hash.
    • issueCredential(credential): Generates did:verichain:xxx, computes hash, mines a CREDENTIAL_ISSUED block, and saves to chain & Supabase.
    • revokeCredential(id, reason): Adds credential ID to revocation set and mines a CREDENTIAL_REVOKED block.
    • verifyCredential(payload): Hashes scanned QR payload, checks revocation list, finds issue block, and verifies computedHash === storedHash.
  • server/index.js:
    • rateLimiter: Limits requests to 30 req/min per IP to prevent credential brute-forcing.
    • POST /api/auth/send-otp & /api/auth/verify-otp: Dispatches 6-digit verification code via Brevo Email API with account lockout protection.
    • POST /api/credentials/issue, /verify, /revoke: Core API endpoints.

Frontend Interface (src/components/)

  • LandingPage.jsx: SIH Presentation dashboard with an Interactive Verification Playground for judges.
  • HolderWallet.jsx: Citizen digital wallet with dynamic QR generation, Active/Revoked/Expired tabs, Privacy Mode masking, and Self-Revocation.
  • IssuerPortal.jsx: GovTech authority desk to issue verifiable DIDs and revoke credentials by citizen email.
  • VerifierPortal.jsx: Live camera QR scanner and instant cryptographic validation display.
  • BlockchainExplorer.jsx: Public live audit ledger stream showing blocks, headers, and previous hash linkage.
  • AdminPortal.jsx: Master Admin governance panel to assign and change user roles in real time.

5. Top Judge Questions & Winning Answers

Q1: "Why use blockchain instead of a standard SQL database?"
Answer: In a standard database, any database admin or hacker with SQL access can silently alter records without a trace. In VeriChain, each credential issue and revocation is an immutable, cryptographically chained block linked to the previous block's SHA-256 header hash. Modifying any past record breaks the mathematical hash chain.
Q2: "How do you handle Indian data privacy and DPDP Act 2023 compliance?"
Answer: VeriChain enforces Zero Raw PII On-Chain. The citizen's personal data (Aadhaar, Passport, Name) never touches the blockchain. Only the 64-character SHA-256 hash digest is stored. Because SHA-256 is a one-way mathematical function, citizen data can never be reverse-engineered from the blockchain.
Q3: "What happens if a tourist alters their Aadhaar number on their phone?"
Answer: Changing even a single digit changes the SHA-256 hash completely due to the avalanche effect. When the hotel scanner recalculates the hash of the presented QR payload, it will mismatch the on-chain hash, immediately raising a 'SECURITY ALERT: TAMPER DETECTED' warning.
Q4: "How does Revocation work if blockchain is immutable?"
Answer: We do not delete old blocks. Instead, when an authority or citizen revokes a credential, a new CREDENTIAL_REVOKED block transaction is mined onto the ledger and the ID is added to the active revocation registry. When verifying, the verifier checks both hash validity AND the revocation status.
